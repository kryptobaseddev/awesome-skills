# The Council — Is deluxui a design director or only a UX auditor, and what is the minimum addition that would make it both?

## Restated question

Should deluxui acquire a generative design-craft capability (and the enforcement of its own 20 inert UX laws), or should it stay a pure verification engine and cede design composition to the model's own knowledge — and if the former, what is the smallest set of additions that survives its NOT_RUN evidence discipline?

## Evidence pack

1. `skills/deluxui/references/rules/detectors.yaml` + `references/rules/registry.yaml` — **The 20 UX laws are inert.** `LAW-*` appears 0 times in detectors.yaml, 0 times in ux_report.py, and only as scattered single mentions in prose. No rule cites a law as its `basis` (that field carries S00–S46 only). Section 04 of the owner's rulebook declares `law_contract_defaults: enforcement: Project policy for applicable interfaces`, and the original plan claimed "19 enforceable LAW- contracts". The design-reasoning layer is carried as data and consumed by nothing. Rationale: this is the single largest gap between what the constitution promises and what the skill does, and it sits exactly on the axis the owner cares about.

2. `skills/deluxui/references/workflows/create.md:28-31` — the build order is "**Semantics, then states, then looks.** Role, name and keyboard behaviour first; then make every state reachable; then style it." The file then gives seven specifics, all of them engineering (native elements, headless primitives, CLS reservation, empty states, pending states, undo). **There is no guidance of any kind on how to style it.** Rationale: the generative moment is exactly where the skill goes silent.

3. Grep across all of `skills/deluxui/references/**` returns **zero files** for `colour ramp`/`color ramp`, `focal point`/`visual weight`, `grid system`/`column grid`/`layout grammar`, and `elevation`/`depth system`. ### Advisor: Contrarian

**Frame:** Assume the plan is wrong. What fails first? What's been overlooked? Why is this a worse idea than it looks?

**Findings (failure modes, from my frame only):**

A craft rule has no computable engine (item 7), so it is bound to a manual detector; `ux_report.py:531` ingests `status: PASS` plus free-text `evidence` straight from `manual.yaml`, written by the same agent that made the design decision. The self-audit was built to catch invented results and it will actively certify this one. The asymmetric cost the ladder exists to price in — "being wrong about departing rewrites someone's product in a style they never asked for" (`SKILL.md:139-141`) — is realised by two skills each correctly following its own instructions. Detected: silently; the run ends READY, with a redesign nobody requested and both project-memory files internally consistent.

3. **A layer that cannot fail, cannot regress, and therefore cannot be maintained** — triggers at the first substantive edit after the craft layer ships, i.e. within one release. Evidence-pack item 6 is the trap: knowledge-shaped assertions scored 17/18 with the skill and 17/18 without it, zero delta. Design craft is knowledge-shaped by construction, so the existing eval harness **cannot distinguish "the craft layer works" from "Opus 5 already knew this"** — every A/B run on a craft addition returns a null result that reads as a pass. Nothing else covers it either: `scripts/selftest.py` asserts detectors fire on known-bad fixtures, and there is no fixture shape for "this palette is incoherent"; `scripts/lint_rules.py` checks ID existence and detector reachability, not whether prose still describes the system. So the craft layer enters the repo with no test that can go red, in a codebase whose entire thesis is that unverifiable claims are the defect. The severity choice then forecloses both exits: file craft rules **P2** and `ux_report.py:599` never blocks on them, so they accumulate as a permanent NOT_RUN tail on every report — which trains the reader to skim the NOT_RUN column, destroying the one discipline the skill sells; file them **P1** and the gate starts BLOCKING on taste, where the cheapest unblock available to any future maintainer under deadline is a line of YAML (finding 1). Detected: by a new reader six months out who stops believing the NOT_RUN column, and then stops believing the PASS column.

**Verdict from this lens:** The fatal flaw is not that a craft layer would be bad design guidance — it is that every mechanism deluxui uses to make claims checkable is inverted the moment it carries claims that cannot be checked: the manual tier becomes an attestation laundry (`ux_report.py:531`), the self-audit becomes its notary (`:355-369`), the orphan lint is already exempt for exactly this class of rule (`lint_rules.py:37` vs `:123`), and the eval harness returns a guaranteed null result (item 6). Adding craft to *this* architecture does not extend it; it supplies the one input shape that defeats it. And the failure is silent in all three findings — the artefact keeps looking like a verdict while it stops being one.

**Single sharpest point:** The first craft rule to reach a release audit will be attested `status: PASS` in `manual.yaml` by the same agent that made the design choice, and `self_audit`'s GOV-006 will print *"All N PASS rules name the detector that produced them"* — the honesty machinery certifying the one claim nobody can check, which is precisely the laundering commit `a5f431d` was written to stop.

### Advisor: First Principles

**Frame:** Ignore everything that was said. What is actually true here? Break this down to first principles and answer from zero.

**Evidence anchored:**

- **W3C WCAG 2.2, Conformance Requirements + "Understanding Conformance"** — success criteria are written as *testable statements* and are held apart from advisory techniques, which are explicitly non-normative. This is atomic: the most successful design-quality contract in existence achieved its authority by refusing to make any claim it could not route to a decision procedure. It did not get there by having more prose about good design.
- **W3C ARIA Authoring Practices Guide (APG)** — a named pattern (dialog, combobox, tabs) is checkable *because it is a declaration made before the code*. "Does this match the APG dialog pattern" is decidable; "is this dialog well designed" is not. The difference is the prior declaration, not the subject matter.
- **Evidence pack item 6** (`memory/deluxui-skill.md` A/B) — knowledge-shaped assertions 17/18 with the skill vs 17/18 without; verifiability-shaped 15/18 vs 1/18. Measured, on this model, on this skill.
- **Evidence pack item 2** → `skills/deluxui/references/workflows/create.md:28-30` — "Semantics, then states, then looks. Role, name and keyboard behaviour first; then make every state reachable; **then style it.**" Overlay: the build order names the generative moment and then emits nothing at it.
- `skills/deluxui/references/rules/registry.yaml:2542` — `laws:` is a **top-level sibling of `rules:`**, carrying `MUST` / `MUST_NOT` / `verify` / `sources` but no `severity`, no `class`, no `applies_when`, no detector binding. `LAW-` appears 22× in registry.yaml and 0× in detectors.yaml. Overlay only.
- `skills/deluxui/references/rules/detectors.yaml:106-108` — the comment above the craft detectors: *"Low confidence by design: a deliberate choice looks identical to a reflex from outside, and what separates them is whether anyone can say why."* Overlay: the artifact has already written down the atomic truth below and then not acted on it.

---

**Atomic truths (independent of the artifact):**

1. **Design is a mapping from constraints to choices.** A generalist language model holds the mapping (ramps, scales, hierarchy, Gestalt grouping) at high fidelity. What it lacks is (a) *this* product's constraints and (b) any perception of the rendered result. A human designer's loop is emit → look → adjust; an agent's loop is emit → assert. That is a sensory and contextual deficit, not a knowledge deficit.

2. **In-context prose cannot raise a model's ceiling on knowledge it already holds.** It can only change three things: the procedure, the stopping condition, and what the agent is forced to look at. Any addition whose stated value is "teaches the agent about colour ramps" is a priori near-zero-yield against a model that can already recite the ramp.

3. **A claim is checkable if and only if a decision procedure exists whose source of truth lies outside the claimant.** For claims about an interface there are exactly three such sources: **an external standard** (WCAG, a platform HIG, APG), **a prior declaration** (a commitment recorded before or at the moment of choosing), or **an observed outcome** (a usability session, field telemetry). There is no fourth. A claim with no source of truth outside the agent is not a weak claim — it is not a claim.

4. **Therefore "is this good?" is not a checkable predicate, and "does this conform to what was declared?" is.** Conformance-checking never requires anyone to adjudicate the declaration itself. This is the load-bearing move: it *removes taste from the verdict* rather than resolving taste. It is also why the tells in evidence pack item 4 are all detectable in principle — a purple gradient, a border-plus-shadow, one font at four weights, an accent stripe implying a category system are each an **incoherence** signature, i.e. an artifact feature with no corresponding declaration. `references/anti-slop.md:57-60` states this atom in prose already: *"The escape is not a different style — it is a reason."*

5. **A declaration has discriminating power only if it precedes the choice.** Written afterwards, it is a rationalisation of whatever was emitted, and it will always show conformance. Sequencing is not a convenience here; it is the whole epistemic content of the check.

6. **Coherence is a property of a set, never of an element.** An agent that emits one component per turn cannot observe coherence from inside the emission. An external record of the set is the only instrument that makes it visible — to the agent, and to the next agent six months later.

7. **In a system where "unverified" is a reported status, every unverifiable assertion carries negative marginal value.** It consumes context, invites the agent to attest to it, and dilutes the signal of the claims that *are* checkable. Adding N taste rules with no decision procedure adds N new NOT_RUNs, whose only two fates are reader desensitisation or silencing. Volume of design prose and strength of an evidence gate are not independent quantities — they trade against each other.

---

**Reconstructed solution (from atoms, before reading the plan):**

From atoms 1, 5 and 6, the generative moment must be forced to emit **two** artifacts, not one: the code, and a small fixed-arity record of the visual commitments made — which semantic colour roles and which ramp steps are in play, which type roles, the spacing base, the *one* depth metaphor, the focal element of this view, the column grammar. From atoms 3 and 4, the skill's contribution is then a **conformance engine, not a taste engine**: it checks that the artifact matches the record and that the record is internally consistent, and it never rules on whether the record is beautiful. From atom 2 it supplies **no new design prose at all** — the model already picks a competent ramp; what it will not do unprompted is say out loud which ramp it picked, and that saying-out-loud is the entire deliverable. From atom 7, every claim the addition introduces must land in one of the fates the system already has (automated, human-attested, not-applicable, NOT_RUN) before it ships, so a named human attestation is a *success* for the residue, not a shortfall. And the 20 laws enter by exactly the same gate or not at all: each law's `verify:` clause is partitioned into standard-checkable, declaration-checkable, or human-only, and the human-only remainder is named as an attestation rather than carried silently as data.

---

**Reconstruction vs. the proposed plan:**

**Convergences (the strong ones — the machinery already exists, built for a neighbouring purpose):**

The skill has already proven the "declare at the moment of choosing, then check against the declaration" architecture works. It applied it to semantics and states and stopped.
- `assets/templates/DESIGN.md` already asks for almost exactly the declaration my reconstruction needs: semantic colour roles and colour space, type roles and scale, spacing base unit, themes, motion defaults, density — and, verbatim on elevation, *"Pick one metaphor."* The declaration content is drafted; nothing reads it.

- The four-fate status vocabulary (rulebook §19 `release_policy`, registry `status_vocabulary`) is atom 7 implemented. `references/verification/manual-checks.md` is the correct and already-built home for the human residue.
- `detectors.yaml:106-108` names atom 4 exactly — *"what separates them is whether anyone can say why."*

**Divergences, each classified:**

- **`create.md:28-30` stops one step short of the generative moment** — *path-dependent cruft*. The file was written from the checkability frontier as it stood: semantics had detectors to point at, states had probes, looks had neither, so the sentence ends at "then style it." Not an authoring lapse. But by atom 5 this is the one load-bearing gap in the skill, because a choice not recorded at this instant is uncheckable *forever downstream* — every later design verdict inherits the absence.

- **The gap is read as missing *guidance* when it is missing *capture*** — *genuine error, and the most consequential one*. Evidence pack item 3 (zero files on colour ramp, focal point, grid, elevation) and item 5 (impeccable's 6,576 prose lines vs deluxui's 1,079) both frame the deficit as absent knowledge. Atom 2 and item 6's measured **zero delta** on knowledge-shaped assertions say the prose deficit is worth approximately nothing against this model. What impeccable has that actually matters is not `colorize.md`'s 257 lines of colour theory — it is that a named operation *makes a choice and names it*, which incidentally produces a record. The transferable asset is the record-making, not the prose. Matching a line count optimises the one axis the A/B measured as flat, while atom 7 says the added NOT_RUNs make the gate measurably worse.

One artifact for the human, one for the comparator, generated from the same inspection pass `init` already performs.

Cruft: imported wholesale from rulebook §04 and never triaged, which is the ordinary fate of a knowledge layer that arrived before its consumers. Holding all three at the same zero-enforcement status asserts they are the same kind of claim, and they are three different kinds. Meanwhile §04 declares `enforcement: Project policy for applicable interfaces`, so the artifact routes a claim its own machinery does not carry.

- **The question's framing — generative capability *or* pure verification engine** — *genuine error, in the decomposition itself*. The two are not substitutes and the choice is not available. There is no "pure verification engine" for composition, because verification requires something declared to verify against, and declaring it **is** the generative act. Equally there is no useful prose-shaped "generative capability," because the model already holds the prose (item 6) and unbound prose degrades the gate (atom 7). The real axis is one-dimensional: **does the skill capture design intent at the moment of choosing — yes or no.** Today, no. "Design quality" is the wrong decomposition; **declared coherence** is the right one, and it is verifiable by construction.

---

**Verdict from this lens:** The architecture holds up and the diagnosis does not. Every atom my reconstruction needs is already built into this skill — declare-then-check (`component-contract.md`), a drafted declaration (`DESIGN.md`), derivation-by-inspection (`init.md`), and a four-fate status vocabulary — and they are wired to semantics and states but not to looks. The minimum addition that survives NOT_RUN discipline is therefore not a design-craft library: it is a **visual contract** (a machine sibling to DESIGN.md, derived at `init`, extended at the `create.md:28` line), detectors that diff artifact against it in place of the five low-confidence intent-guessers, and the `laws:` block triaged into its three real fates with the human residue named as `M-*` attestations. That is roughly zero new lines of design prose, it lands every new claim in an existing fate, and it makes the anti-slop catalogue's entries decidable by giving them the one thing they lack — a stated reason to compare against.

**Single sharpest point:** A design claim becomes checkable only against a declaration made *before* the choice — so the hole at `create.md:28-30` is not missing styling guidance, it is a missing styling **record**, and that one absence is why every design verdict in a 190-rule skill is either an external standard, a low-confidence guess, or nothing.

### Advisor: Expansionist

**Frame:** Forget the constraints. What's the biggest version of this? What opportunity is sitting right in front of us that nobody is talking about?

### Conditions on the recommendation
