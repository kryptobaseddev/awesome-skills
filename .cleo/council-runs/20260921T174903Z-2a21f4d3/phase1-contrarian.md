**Findings (failure modes, from my frame only):**

1. **Taste laundered into a PASS, then notarised by the report's own honesty audit** — triggers the first time an agent adds craft rules to its own work and runs `ux_report.py --merge` in the same session. A craft rule has no computable engine (item 7), so it is bound to a manual detector; `ux_report.py:531` ingests `status: PASS` plus free-text `evidence` straight from `manual.yaml`, written by the same agent that made the design decision. The `self_audit` then runs GOV-006 (`ux_report.py:355-369`) and emits *"All N PASS rules name the detector that produced them"* — because a manual attestation **is** a named detector that reported PASS. The self-audit was built to catch invented results and it will actively certify this one. If the craft rule carries P0 or the agent attests the remaining manual P0s in the same pass, `unchecked_p0` empties and the decision moves CONDITIONAL → READY (`:611-615`). Fails by converting the one artefact in this skill that a reader can trust — the matrix, whose whole value per item 6 is the 15/18-vs-1/18 verifiability delta — into a document where falsifiable contrast measurements and unfalsifiable "the ramp is harmonious" sit in the same column with the same word next to them. **Detected: silently, and worse than silently — the report affirms it.** Commit `a5f431d` proves this exact laundering shape already escaped review once, when it was arithmetically obvious (one file → 116 PASS); a prose attestation leaves no anomaly to notice.

2. **Two co-resident skills claim the same job, and the preserve ladder's anchor becomes invisible** — triggers the first time a user with both installed says "polish this dashboard." Today deluxui and impeccable co-exist in `~/.agents/skills/` without contradiction precisely *because* deluxui has no craft surface: a model reads them as auditor plus designer. Add colour/type/layout guidance and both descriptions now assert ownership of the same request — `skills/deluxui/SKILL.md:18` ("redesigning, polishing … 'make this look better'") against impeccable's ("design, redesign … polish, clarify, distill, harden … colorize"). The resolution is not a merge; it is whichever ritual the model executes first, and both rituals are written as mandatory: impeccable `SKILL.md:11-15` makes `context.mjs` a MUST, `reference/<register>.md` "non-optional", and `palette.mjs` the authority for a brand seed colour on any project without committed tokens. Fails by path divergence, not by argument: `context.mjs:7-12` resolves PRODUCT.md from cwd / `.agents/context` / `docs` and never reads `.deluxui/`, so a project initialised by deluxui presents as `NO_PRODUCT_MD` to impeccable, which then writes a second, conflicting DESIGN.md — and the identity that `references/preserve.md` and the PRESERVE ladder are anchored on (`SKILL.md:143-146`: "Departure needs an explicit request, or a PRODUCT.md anti-reference aimed at *this specific surface*") stops governing anything, because the palette authority is reading a different file. The asymmetric cost the ladder exists to price in — "being wrong about departing rewrites someone's product in a style they never asked for" (`SKILL.md:139-141`) — is realised by two skills each correctly following its own instructions. Detected: silently; the run ends READY, with a redesign nobody requested and both project-memory files internally consistent.

3. **A layer that cannot fail, cannot regress, and therefore cannot be maintained** — triggers at the first substantive edit after the craft layer ships, i.e. within one release. Evidence-pack item 6 is the trap: knowledge-shaped assertions scored 17/18 with the skill and 17/18 without it, zero delta. Design craft is knowledge-shaped by construction, so the existing eval harness **cannot distinguish "the craft layer works" from "Opus 5 already knew this"** — every A/B run on a craft addition returns a null result that reads as a pass. Nothing else covers it either: `scripts/selftest.py` asserts detectors fire on known-bad fixtures, and there is no fixture shape for "this palette is incoherent"; `scripts/lint_rules.py` checks ID existence and detector reachability, not whether prose still describes the system. So the craft layer enters the repo with no test that can go red, in a codebase whose entire thesis is that unverifiable claims are the defect. The severity choice then forecloses both exits: file craft rules **P2** and `ux_report.py:599` never blocks on them, so they accumulate as a permanent NOT_RUN tail on every report — which trains the reader to skim the NOT_RUN column, destroying the one discipline the skill sells; file them **P1** and the gate starts BLOCKING on taste, where the cheapest unblock available to any future maintainer under deadline is a line of YAML (finding 1). Keeping the 20 laws in the `laws:` block dodges the lint but preserves the two-tier citation already visible at `references/anti-slop.md:66`, where LAW-12 is cited as a failure the matrix has never adjudicated; moving them into `rules:` without detectors makes `lint_rules.py:123` error on 20 fresh orphans and the next maintainer's fastest fix is a manual detector for each — which is finding 1, twenty times over. Detected: by a new reader six months out who stops believing the NOT_RUN column, and then stops believing the PASS column.

**Verdict from this lens:** The fatal flaw is not that a craft layer would be bad design guidance — it is that every mechanism deluxui uses to make claims checkable is inverted the moment it carries claims that cannot be checked: the manual tier becomes an attestation laundry (`ux_report.py:531`), the self-audit becomes its notary (`:355-369`), the orphan lint is already exempt for exactly this class of rule (`lint_rules.py:37` vs `:123`), and the eval harness returns a guaranteed null result (item 6). Adding craft to *this* architecture does not extend it; it supplies the one input shape that defeats it. And the failure is silent in all three findings — the artefact keeps looking like a verdict while it stops being one.

**Single sharpest point:** The first craft rule to reach a release audit will be attested `status: PASS` in `manual.yaml` by the same agent that made the design choice, and `self_audit`'s GOV-006 will print *"All N PASS rules name the detector that produced them"* — the honesty machinery certifying the one claim nobody can check, which is precisely the laundering commit `a5f431d` was written to stop.
