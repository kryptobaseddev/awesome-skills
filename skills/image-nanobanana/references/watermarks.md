# Watermarks and Provenance — Reference

Read this when the user asks about watermarks ("no watermark", "remove the
sparkle", "is this watermarked?"), provenance, or whether generated assets are
safe to ship in production.

## The two watermarks

Google applies two completely different marks to Gemini-generated images:

| | Visible "Gemini sparkle" | Invisible SynthID |
|---|---|---|
| What | A visible logo overlay in the corner | Imperceptible signal embedded in pixels |
| Where applied | Consumer **Gemini app** only, for free and Google AI Pro tier users | **Every** image from every Google generation surface, no exceptions |
| Affects production assets? | Yes — visibly | No — invisible, survives crops/compression by design |
| Can it be avoided? | Yes — generate through the right surface (below) | No — and don't try (see ethics note) |

## Which generation paths produce sparkle-free images

| Surface | Visible sparkle? | Notes |
|---|---|---|
| Gemini app — free / AI Pro tier | **YES** | Never use for production assets |
| Gemini app — AI Ultra tier | No | Google removed it for Ultra subscribers |
| Google AI Studio (web) | No | Google removed it "within the Google AI Studio developer tool" |
| **Gemini API (paid key)** — what this skill uses | No visible watermark | API docs state only: "All generated images include a SynthID watermark." Image models are paid-only on the API, and API output carries no sparkle overlay per Google's tier policy and observed behavior |
| gemini-cli + nanobanana extension | Same as API | It IS the API (your key, your billing) |

Bottom line: **everything this skill generates (nb-generate.py or the
gemini-cli extension) ships without a visible watermark** — consistent with
Google's published tier policy and observed API behavior, not a removal trick.
(Google's own docs only guarantee the invisible SynthID mark; the sparkle
policy comes from their product blog, which scopes the overlay to consumer
Gemini-app free/Pro tiers.)

## SynthID: leave it alone

- SynthID is embedded at generation time in every output. It is invisible,
  doesn't affect visual quality, and exists so AI-generated media can be
  identified (Google's Gemini app can detect it: upload an image and ask
  "Was this generated by AI?").
- **Do not attempt to strip, distort, or defeat SynthID.** It serves
  provenance and platform-integrity purposes; removing it can violate
  Google's Generative AI Prohibited Use Policy and undermines trust in the
  assets you ship. No script in this skill modifies generated pixels, and
  none should be added that does.
- SynthID is not a usage restriction: assets generated through the paid API
  can be used commercially under Google's terms — the watermark just records
  that the image is AI-generated.

## If the user has sparkle-watermarked images already

They came from the consumer Gemini app (free/Pro tier). The correct fix is to
**regenerate** the asset through the API path with the same prompt (and the
original image as a reference if composition must match) — not to edit the
watermark out. Editing out a watermark from an image the user didn't generate
themselves is also a copyright red flag; decline those requests.
