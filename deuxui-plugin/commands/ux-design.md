Run the deuxui `design` workflow for $ARGUMENTS.

Invoke the `deuxui` skill, then follow its `design` workflow
(`references/workflows/design.md`).

Pick the visitor mode first — it decides density, colour dosage and motion budget, and
getting it wrong makes the craft irrelevant. Commit to a world in observable values, not
moods. Then write `.deuxui/design.contract.yaml` **before** the code: a contract written
afterwards describes whatever got emitted and always shows conformance.
